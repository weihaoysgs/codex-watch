# 候响 · Codex Watch 0.6.1 — Ubuntu 安装包

只盯正在工作的 Codex，完成后弹窗提醒，点击“知道了”便移出列表。

## 系统要求

- Ubuntu 图形桌面，Python 3.8 或更高版本、PyQt5 5.14 或更高版本。
- Ubuntu 20.04：已在隔离容器中验证原生 Python 3.8.10 / PyQt5 5.14.1 / Qt 5.12.8 的安装、57 项测试和 Xvfb 中的真实 Fcitx 拼音输入；尚未在独立 20.04 GNOME 桌面实测。
- Ubuntu 22.04：已在 X11 桌面验证提醒，并在隔离 Xvfb 中验证 Qt 5.15.3 下的真实 Fcitx、IBus 拼音输入。Ubuntu 24.04 等满足依赖的版本可尝试安装，但尚未在独立机器或 Wayland 桌面验证。
- 安装包是纯 Python、架构无关（`all`）；依赖由 Ubuntu 安装对应架构版本。ARM64 尚未实机验证。
- 已安装并使用过 Codex；候响不会替你安装或登录 Codex。
- 默认读取当前用户的 `~/.codex`。如果更改了位置，以 `CODEX_HOME=/你的目录 codex-watch` 启动。
- 安装时需要联网下载尚未安装的系统依赖，日常监控本身不需要联网。

## Ubuntu 20.04 安装问题

0.5.0 及之前安装包的 Python / PyQt5 最低版本要求过高，Ubuntu 20.04 会提示依赖无法满足。请改用 **0.5.1 或更新版本**；不要强制安装旧包，也不需要替换系统 Python 或添加第三方源。0.5.1 同时修复了 Python 3.8 下的终端识别和旧 Qt 下的标题栏拖动。

## 安装

解压分享包，在包含 `.deb` 的目录中打开终端：

```sh
sudo apt install ./codex-watch_0.6.1_all.deb
```

推荐使用 `apt install ./…deb`，它会自动处理 Python、PyQt5 等依赖。也可用系统的软件安装器打开 `.deb`。

安装后在应用菜单搜索 **候响** / **Codex Watch**，或运行：

```sh
codex-watch
```

**不要使用 sudo 启动应用**：它需要读取当前用户的 Codex 会话，并连接当前桌面。

## 使用

1. 先打开候响，然后照常使用 Codex；已在进行中的工作也会自动被识别。
2. 仅显示进行中的工作与等待你确认的新提醒，不导入历史完成记录。
3. 工作时桌面猫咪持续活动；完成、需要回复或出错时，在宠物旁弹出文字气泡，不自动消失。收起宠物后仍显示独立置顶卡片。
4. 点击“查看这项工作”打开详情；“知道了”移出列表；“稍后”仅收起弹窗。
5. 左侧「会话目录」按项目路径列出当前用户已索引的会话（包括较早和已归档记录）；点选查看最近信息，不会加入提醒或修改会话。
6. 关闭主窗口仍在托盘监控。真正退出用托盘菜单或 `Ctrl+Q`。

“外观与提醒”里可切换猫 / 狗 / 不显示宠物、深浅色、来回跑动、提示音及登录自启动，也能预览完成提醒。**默认文字提醒、不播放提示音**；自启动默认关闭。

### 中文搜索

0.6.1 修复了后台重绘列表时打断拼音组词、提前上屏的问题。升级后请确认托盘旧进程已退出，再重新打开应用。组词期间任务监控与完成提醒不暂停，搜索结果在中文提交后更新。

若完全没有候选框且其他 Qt 应用同样异常，检查输入法的 Qt5 插件：Fcitx 4／搜狗使用 `fcitx-frontend-qt5`，Fcitx 5 使用 `fcitx5-frontend-qt5`。只补装当前框架对应的插件，不要同时更换输入法，也不需要改系统 Python。

- 宠物可以拖动，位置自动保存；单击查看待确认提醒或当前任务，右键切换猫狗或收起。
- 工作时自动轮换生活小场景：猫咪洗衣服、吃鱼、追老鼠、拨毛线球；小狗洗衣服、啃骨头、追球、接飞盘，穿插跑步、走路和跳跃。没有工作时待机。多个任务中一个完成时单独提醒，其余任务继续计数。
- 右键 →“让它做点什么”，可点播活动 12 秒；仅预览动画，不会改变任务状态。任务完成提醒优先于预览。
- 点击“知道了”仅清除对应提醒，不关闭 Codex。宠物继续留在桌面陪伴；可随时右键收起。
- 动画全部离线内置：角色使用 pzUH / GameArt2D 的 CC0 素材，生活场景由本应用的 Qt 关节动作与矢量道具组合制作；安装包含来源说明。宠物活动不代表 Codex 正在执行同名操作。

置顶卡片不依赖系统通知横幅；系统勿扰不会屏蔽这张应用内卡片，需安静时请使用候响的暂停功能。锁屏、全屏程序或不同桌面合成器的显示行为可能不同。

## 数据与隐私

安装包**不含打包者的会话、配置、账号、截图或其他个人数据**。

- 只读当前用户的 Codex 会话数据库、事件日志及进程会话关联。
- 不读取 `auth.json`，不修改 Codex 配置或会话，不上传内容，也不调用模型 API。
- 自己的设置和已确认标记位于 `~/.local/share/codex-watch/`（或 `XDG_DATA_HOME` 下）。
- 程序文件：`/usr/share/codex-watch/`；命令：`/usr/bin/codex-watch`。

## 升级 / 卸载

升级前从托盘退出旧版，再用 `sudo apt install ./新版.deb` 安装；用户设置会保留。

卸载前从托盘退出，并在设置里关闭登录自启动，然后运行：

```sh
sudo apt remove codex-watch
```

卸载不会删除个人偏好和已确认标记。彻底清理时，可手动删除 `~/.local/share/codex-watch/` 与 `~/.config/autostart/io.local.CodexWatch.desktop`；请仅删除这两个候响专用路径，不要删除 `~/.codex`。

## 已知兼容性边界

- 适配的是本地 Codex SQLite / JSONL 结构，而非稳定公共 API；Codex 升级后可能需要更新。已验证的当前环境包含 Codex 0.159.2。
- 同时兼容独立 CLI 与共享 app-server；某些 CLI 会话的内部来源标签为 `vscode`，也会正常监控。
- 不能保证识别所有版本的交互审批；只有本地日志中的明确事件可被识别。
- 共享后台不一定能关联到具体终端标签页，因此按会话名称识别，不猜窗口编号。
- 不自动切换到已有终端窗口，不发送按键，不关闭实际 Codex 会话。
- 候响退出后不再实时提醒；已跟踪的未确认完成记录会在重启后恢复。

## 排查

```sh
codex-watch --version
codex-watch --diagnose
```

诊断输出含工作目录与会话 ID，分享前请检查；不输出标题、回复或问题正文。
如果提示找不到会话索引，请先运行一次 Codex 并确认 `CODEX_HOME` 位置。检查弹窗可使用设置中的“预览完成提醒弹窗”。
